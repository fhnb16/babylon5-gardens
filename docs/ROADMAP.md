# Дорожная карта: общее ядро, three.js r187 + WebGPU, свой path tracer, бэкенд ThreeRT

Это чистовая версия утверждённого плана развития. Подробная история решений
до версии 2.10.x — в [design-log.md](design-log.md), обзор проекта — в
[README.md](../README.md), правила для участников и ИИ-агентов — в
[AGENTS.md](../AGENTS.md).

**Статус v2.13.0.** Фоторежим подключён к собственному PT на WebGPU и локальным весам OIDN. Кадр проходит через общую постобработку на WebGPU или выводится поверх классического растра и WebGL2. Экранные лучи на WebGPU читают нормали и шероховатость из MRT. В ThreeRT появились адаптер запечённой станции, материал-функции и игровая точка входа. Android-оболочка собирает один APK для телефонов, планшетов и ТВ. Обычный пуш запускает сборку в GitHub Actions.

## 1. Контекст

### Исходное состояние до волны 0

- three.js r165 (не Babylon.js: «Вавилон-5» — это сериал), ванильный JS без
  сборщика, зависимости через CDN import map.
- Пролёт по цилиндру О'Нилла: R = 50, L = 300 юнитов, 1 юнит = 10 м.
- Всё процедурное: текстуры на Canvas2D, звук на WebAudio, внешних ассетов нет.

### Что мешает расти

**Path tracer есть только в фоторежиме** — `three-gpu-pathtracer` 0.0.23 на
WebGL2. Адаптер `js/pathtrace.js` (~790 строк) почти целиком состоит из обходов
ограничений библиотеки:

- разворачивание ~17,8 тыс. экземпляров в отдельные меши;
- 20 фиктивных точечных ламп у торцов;
- clearcoat-хак для воды;
- усиление эмиссии ×9;
- BVH строится от секунд до десятков секунд.

**Шейдер корпуса** (вода, пена, рябь, свечение города) — GLSL-инъекция через
`onBeforeCompile` (`js/world.js`). Трассировщик её не видит, а под
`WebGPURenderer` она не работает вовсе.

**ThreeRT (MeshyAI):**

- трассирует лучи только в нативных клиентах на железе с аппаратным RT;
- в браузере это обычный растр three.js;
- сценарии выполняются в QuickJS: нет DOM, Canvas2D и WebAudio.

### Решение

1. Улучшить реализацию на three.js: обновить до r187 и добавить WebGPU.
2. Вынести в движконезависимое **ядро** построение мира, все шейдеры и текстуры.
3. Параллельно вести **два бэкенда**:
   - three.js (WebGPU с автоматическим откатом на WebGL2) **со своим WGSL
     path tracer** — сначала фоторежим, реальное время позже;
   - нативный **ThreeRT**.
4. Написать подробный README (на русском) и AGENTS.md (на английском).
5. Активно распараллеливать работу через агентов.

## 2. Ключевые архитектурные решения

### 2.1. Инструменты: Vite + TypeScript (`allowJs`) + Vitest + ESLint

Сборщик был отложен ещё в дизайн-логе («Vite понадобится при дроблении
шейдеров по файлам») — теперь это время пришло. Что он даёт:

- типизированный контракт `SceneDesc` между четырьмя потребителями;
- module workers вместо хака `import.meta.resolve` в `makeBvhWorker`;
- импорт `.wgsl` через `?raw`;
- сборку ядра одним ESM-файлом для QuickJS.

Деплой не меняется: на выходе по-прежнему статическая папка (`dist/`,
`base: './'`).

### 2.2. Раскладка каталогов

| Каталог | Назначение |
|---|---|
| `core/` | движконезависимое ядро: без зависимостей, совместимо с QuickJS, ES2020 |
| `backends/three/` | растр на three.js r187: WebGPU, откат на WebGL2, классический WebGL на время миграции |
| `pathtracer/` | свой path tracer на WebGPU compute, потребляет `SceneDesc` |
| `backends/threert/` | нативный бэкенд ThreeRT, свой `package.json` |
| `app/` | UI, точка входа, workers |
| `tools/` | снимки мира, запекание, вспомогательные скрипты |
| `docs/` | документация |

Импорт `three` и DOM в `core/**` запрещён правилом ESLint
`no-restricted-imports` и тестом `core/test/purity.test.ts`.

### 2.3. Ядро выдаёт данные, а не объекты three

`buildScene(params) → SceneDesc`, где `SceneDesc` содержит:

- геометрию в типизированных массивах с groups;
- экземпляры с матрицами, цветами и атрибутом `wind`, разбитые на чанки;
- дескрипторы материалов с `ParamRef` на палитру;
- `lodSets`, `billboards`;
- `emitters`: физическую трубу-солнце для трассировщиков и `rasterLights` как
  растровую аппроксимацию;
- `hull`, `dynamics`, `views`;
- тег `role` у каждого меша.

Чистые функции ядра: `lightingAt(phase)`, `classifyLod()`, `stepDynamics()`,
математика полёта, тура и поездки, `terrain.radiusAt(θ, z)`.

- UV корпуса запекаются сразу с правильным направлением θ — хак
  `repeat.x = -1` исчезает для всех бэкендов.
- В config добавляется физическая палитра `PHYS`: яркость трубы в нитах, RGB,
  EV100, яркость окон, туман, `waterTint`, `cityGlow`. Её используют наш PT и
  ThreeRT.

### 2.4. Текстуры: программный растеризатор

`core/raster/` — подмножество `Context2D` (~800 строк): пути,
quad/arc/ellipse, заливка по правилу nonzero с AA, обводка с dash/cap/join,
градиенты, прямоугольный clip, save/restore, `globalAlpha`, даунскейл
`drawImage`.

- Генераторы из `js/textures.js` переносятся почти построчно,
  **порядок вызовов `rnd()` сохраняется**.
- В вебе генерация идёт в пуле workers — фриз 0,4–0,9 с при старте исчезает.
- Для ThreeRT текстуры запекаются в PNG.

### 2.5. Шейдеры — один источник для всех бэкендов

Ядра пишутся на TSL-совместимом подмножестве `K` (`core/shading/kernel.ts`).
Три потребителя:

| Потребитель | Что получается | Для кого |
|---|---|---|
| настоящий `three/tsl` | WGSL и GLSL | WebGPU и откат на WebGL2 |
| эмиттер `core/shading/emit/wgsl.ts` | чистые WGSL-функции `b5_*` | наш PT и `MaterialFunction` в ThreeRT |
| CPU-вычислитель | числа | поведенческие тесты вместо grep по GLSL-строкам |

Правила для ядер:

- текстуры сэмплирует бэкенд и передаёт ядру значения;
- аргумент `footprint` (ширина пикселя или конуса луча) вместо дистанционного
  хака `wFar`;
- в WGSL нет `$` и биндингов, только `f32`;
- только для растра остаются аналитические тени ферм и аналитические
  отражения.

**Запасной вариант**, если подмножество окажется хрупким: канонический WGSL
плюс ручной порт на TSL, CPU-оракул как эталон.

### 2.6. Детерминизм

- Раскладку мира генерирует V8: в браузере — на лету, для ThreeRT — Node при
  запекании (`generated/layout.ts`). Причина: QuickJS и V8 могут расходиться
  на ulp в `Math.sin`, `exp`, `pow`.
- Для проверок `fits` / `inPond` нужна пространственная сетка (сейчас O(n²)).
- Генератор случайных чисел — только сидированный `mulberry32`; порядок
  вызовов `rnd()` фиксирован и проверяется золотыми снимками.

### 2.7. Единицы

Ядро работает в юнитах станции (1 юнит = 10 м). ThreeRT получает
**1 юнит = 1 м**: в live-режиме он отбрасывает излучатели дальше 120 м, а
освещённость от трубы от масштаба не зависит.

### 2.8. Связь path tracer с three

- Общий `GPUDevice` создаёт `pathtracer/device.ts` и передаёт его в
  `new WebGPURenderer({ device })`.
- Выход PT пишется в `StorageTexture` three (`backend.get(tex).texture` —
  единственный внутренний API, закреплён на версии и проверяется самотестом) и
  подаётся в `RenderPipeline` через `pipeline.compositeExternal(hdrNode, exposure)`.
- Форматы AOV: albedo `rgba8`, normal `rgba16f`, depth `r32f`, motion `rg16f`,
  matId `r16u`.

## 3. Организация работы

- Каждая волна оставляет приложение **рабочим**.
- Агенты работают в изолированных worktree и владеют только своими путями.
- Контракты `core/scene/types.ts` и `core/shading/contracts.ts` меняет только
  лид.
- Между волнами — сведение, тесты и короткий отчёт пользователю.
- Для worktree-изоляции нужен `git` в окружении агентов; коммиты делает
  сопровождающий.

### Волна 3 — растр на WebGPU + PT M1 + ThreeRT M1–M2

Растр на WebGPU — **готово**, переключение по умолчанию — **отложено**; PT M1 —
**готово**; подключение PT к приложению (P-INT) и ThreeRT M1–M2 реализованы в 2.13.0.

**Растр** (`backends/three/`) — **готово (R1a, R1b):**

- R1a: `renderer.ts` — `createRenderer({ mode: 'webgpu' | 'webgl2' | 'classic' })`
  с общим `GPUDevice` на WebGPU; `materials/node.ts` и
  `tsl/{kernelBridge,hull,wind,fogfade,billboards,displayOutput}.ts`;
  настройка «Рендерер» и `?renderer=`. Рендерер по умолчанию пока
  **классический**. Ветер считается **до** инстансинга three
  (`WindNodeMaterial` через `setupPosition`): после него нужно второе чтение
  матрицы экземпляра → 18 вершинных атрибутов при лимите 16 (WebGL2) / 8
  буферов (WebGPU); TAA скорость ветра не видит. Points → инстансированные
  спрайты. Два режима вывода: `hdr` (приложение, тонмаппинг в цепочке) и
  `display` (эталонный паритет `tools/core-world`). Паритет с эталонами
  классики: худшее среднее 1.27/255. Импорт: `three` и `three/webgpu` делят
  `three.core.js`; адаптер импортирует `three`, а `three/webgpu` и `three/tsl`
  — только узловые материалы и `tsl/*`.
- R1b: `post/pipeline.ts` — `createRenderPipeline` (RenderPipeline r187;
  встроенные `traa`/`smaa`/`fxaa`/`bloom`, свои лучи от оси, FSR EASU/RCAS,
  ACES совпадает с классикой в пределах 0.56/255 через экспозицию ×0.6,
  `ScaledTRAANode` для масштаба ≠ 1; для нескольких рендеров за тик нужен
  `render(true)`; `bloomImpl: 'classic'` — кандидат на значение по
  умолчанию);
- скриншот через `readRenderTargetPixelsAsync`.

**PT** (`pathtracer/`) — **M1 готово:**

- `scene-upload`, `textures` (массивы по классам размеров, ray cones),
  `materials`;
- `integrator`: волновой фронт, бюджет ≤ 40 мс на submit, timestamp-query;
- ядра `k_raygen`, `args`, `shade v0`, `accumulate`, `resolve`.

**Веха PT M1 — достигнута:** реальная сцена, прямой свет трубы и диффузный GI,
BVH строится быстрее 1 с. **P-INT в 2.13.0:** подключение
`pathtracer/index.ts` к приложению (фоторежим на новом PT вместо
`js/pathtrace.js`) вместе с OIDN (`oidn-webgpu`, `pathtracer/oidn.ts`).

**ThreeRT M1–M4:** адаптер, `hull.mf.ts` и `tube.mf.ts` на
WGSL-ядрах, тесселированная излучающая труба вместо 5 PointLight и
Hemisphere, затем город, деревья (instance color + дизеринг `b5_foliage`) и
башня; игровая логика (см. волну 4).

### Волна 4 — свет и материалы PT + фоторежим растра + ThreeRT M3–M4 · **PT готово**

**PT (W4a, P4) — готово:** источники (equiangular-труба, дерево источников),
BSDF (`std`/`glass`/`water`), откалиброванная `PHYS` в ядре, Sobol,
адаптивные тайлы, à-trous, публичный API `pathtracer/index.ts`. В 2.13.0 добавлены растровый фоторежим WebGPU и нативная игра ThreeRT.

**PT P2 — источники:**

- аналитическая труба: equiangular-выборка по z, видимая половина по φ, MIS;
  калибровка против растровых точечных ламп при экспозиции ≈ 1;
- излучающие треугольники: `k_lightpower`, alias-таблица, затем дерево
  источников для ночи.

Хаки `dimAxisLights`, `addRimLights`, `boostEmissive` и `envScale` уходят.

**PT P3 — материалы:**

- `bsdf_std`: GGX + VNDF, паритет с `MeshStandardMaterial`;
- `bsdf_glass`: тонкий диэлектрик с тенью-пропусканием;
- `bsdf_water`: диэлектрик IOR 1.33 с поглощением Бера–Ламберта, рябью и пеной
  из общих ядер, плюс явный `WATER.f0Boost`.

**Растр фоторежима:** денойзеры на TSL (guide через MRT), экранная
трассировка (`ao` / `ssgi` / `ssr` + аналитика из ядер).

**ThreeRT:** камера в системе станции (мир статичен, камера вращается
`Rz(−ω·dt)`), аналитическая коллизия, полёты, тур и монорельс, физические
палитры через `power` и EV, HUD-таблица телепортов, запечённый звук.

### Волна 5 — финал

### Бэклог: Android TV — скринсейвер и управление с пульта

Цель: собирать проект автоматически в APK, ставить на Android TV как
скринсейвер. Переходы между точками обзора и изменение настроек делаются
кнопками пульта.

**Статус:** пункты 1 и 2 (режим без интерфейса, слой действий, оверлей
настроек на D-pad) — **готово в волне 2**: `?mode=tv` (`app/tv-mode.ts`,
`app/tv.ts`), `app/input/actions.ts`, `app/input/remote.ts`, `gamepad.ts`,
`app/ui/tv-overlay.ts`; тесты — `test/actions.test.ts` и сценарий ТВ-режима
в `tests/browser/smoke.spec.ts`. В 2.13.0 добавлены упаковка APK, интерактивный `DreamService`, подпись в Actions и обновления из GitHub Releases. Остались замеры производительности и проверка на реальном пульте.

**1. Режим без интерфейса («TV / киоск») — готово.**
- Включается параметром `?mode=tv`, настройкой или автоматически в APK.
- Не показывает ни одного элемента UI: HUD, кнопки, шторки настроек,
  подсказки, курсор, джойстик.
- Без pointer lock. По умолчанию — авто-тур по точкам обзора и авто-цикл
  день → закат → ночь.
- Экран не гаснет (Wake Lock API в браузере, `FLAG_KEEP_SCREEN_ON` в APK).

**2. Управление с пульта (D-pad) — готово.**
- Слой действий вместо прямой привязки к клавишам: `nextView`, `prevView`,
  `toggleTour`, `cyclePhase`, `openSettings`, `back`… Клавиатура, касания,
  геймпад и пульт отображаются на одни и те же действия.
  Закладывается в волне 2 при разнесении `main.js` по `app/*` (юнит B4).
- Раскладка по умолчанию:

  | Кнопка | Действие |
  |---|---|
  | ← / → | предыдущая / следующая точка обзора (перелёт) |
  | OK | пауза / продолжение авто-тура |
  | ↑ / ↓ | фаза дня |
  | Меню или долгое OK | экранное меню |
  | Назад | закрыть меню |
  | Play/Pause | пауза / продолжение |

- В меню настроек целиком ходит D-pad: фокусная навигация, крупные элементы
  для 10-футового интерфейса, авто-скрытие через несколько секунд.
  Настройки те же, что в обычном UI: качество, сезон, зерно, фаза, скорость
  тура, звук.
- Коды клавиш: `ArrowUp/Down/Left/Right`, `Enter`, `Escape`/`GoBack`
  (Back), `MediaPlayPause`, `ContextMenu`, `ChannelUp/Down`. Проверить на
  реальном пульте.

**3. Сборка APK — реализована.**
- Нативная Kotlin-оболочка загружает ресурсы Vite из APK через WebViewAssetLoader. При обычном запуске режим интерфейса определяется системным типом устройства.
- Скринсейвер — Android `DreamService` (Daydream), внутри которого WebView
  с `dist/`. Это небольшой нативный класс (Kotlin), отдельно от обычной
  Activity-лаунчера.
- Манифест для TV: `android.software.leanback`, `touchscreen required=false`,
  баннер для лаунчера, категория `LEANBACK_LAUNCHER`.
- GitHub Actions при пуше проверяет веб-приложение и собирает APK. Для опубликованного релиза тег сверяется с версией приложения, подписанный APK прикрепляется к GitHub Release.

**4. Производительность на TV — осталась проверка на устройствах.**
- ТВ-чипы слабые. По умолчанию пресет LOW, адаптивное разрешение, без
  фоторежима и path tracer.
- WebGPU в Android WebView есть не везде. Рабочий путь — WebGL2-откат
  WebGPURenderer.
- ThreeRT: Android-клиент существует (Vulkan ray queries), но в ТВ-приставках
  аппаратного RT обычно нет. Не цель этого пункта.

В 2.13.0 пресет AUTO выбирает на телевизоре LOW. Если нагрузка растёт при плотности 1×, разрешение опускается по ступеням FSR.

## 6. Проверка

**Каждая волна:**

- `npm test` (Vitest: core, бэкенды, CPU-эталоны PT) и `npm run build`;
- `npm run dev` и Playwright-смоук по 9 видовым точкам (`views`): нет ошибок
  компиляции, пробные пиксели (вода темнее травы, ночью горят окна, лучи от
  трубы), эталонные скриншоты с допуском.

**Ядро:**

- снимки мира совпадают (допуск 1e-5) с золотыми из волны 0;
- тест чистоты (`core/test/purity.test.ts`);
- parity примитивов с three;
- WGSL-выход ядер парсится `wgsl_reflect`;
- поведенческие тесты ядер на CPU.

**Path tracer:**

- BVH против полного перебора и `three-mesh-bvh raycastFirst`;
- хи-квадрат для alias-таблицы;
- PDF трубы против численной квадратуры;
- опционально GPU-тесты через пакет `webgpu` (Dawn): furnace-цилиндр
  `Le / (1 − ρ)`, BSDF-печь;
- `pt-smoke.html` выдаёт PASS/FAIL.

**ThreeRT:**

- на каждое изменение — `threert check` и `tools/qjs-check.mjs` (время и
  паритет хешей под QuickJS, нет запрещённых глобалов);
- матрица 9 видов × 3 фазы через `tools/shots.mjs` с ΔE против эталонов;
- ручной чек-лист: труба светит без точечных ламп, тени, отражения в воде,
  окна ночью, нет утечек света на торцах.

|---|---|
| Сбой порядка `rnd()` при извлечении раскладки | золотые снимки мира |
